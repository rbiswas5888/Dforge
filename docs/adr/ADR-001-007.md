# ADR-001: Renderer Technology

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** DesignForge AI needs a high-performance canvas renderer capable of handling hundreds of nodes at 60fps with accurate hit testing, selection handles, and guides.

## Decision
Use the **Canvas 2D API** for the POC phase, with the renderer hidden behind a `RendererAdapter` interface for future replacement.

## Rationale
- Canvas 2D is universally supported with no dependencies
- Appropriate for the POC scale (< 500 nodes)
- Clear upgrade path to WebGL/WebGPU when performance data justifies it
- Avoids premature optimization

## Consequences
- Positive: Fast to implement, debuggable, no vendor lock-in
- Negative: Will need GPU acceleration for large documents; SVG paths need manual rendering logic

## Upgrade Path
Replace `CanvasRenderer` class with a WebGL/Skia-based implementation when benchmark documents exceed 16ms frame times.

# ADR-002: Document Model Storage

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** The canonical document must be stable, traversable, serializable, and support partial updates without full rewrites.

## Decision
Use a **normalized flat map** (NodeId → Node) with separate ordered ID arrays for child relationships. This matches how Figma and similar tools store their documents.

## Rationale
- O(1) node lookup by ID
- Easy to diff and patch for AI edits
- Supports collaborative operation protocols later
- Serializes cleanly to JSON

## Consequences
- Positive: Fast lookup, safe mutations, clean serialization
- Negative: Tree traversal requires helper functions

# ADR-003: Undo/Redo Strategy

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** Undo/redo must handle both manual edits and AI batch operations with grouped transactions.

## Decision
Use **inverse-operation records** for small mutations. Use **snapshot deltas** for large AI-generated batches. Store history as a bounded array of named transactions.

## Rationale
- Inverse operations are cheap for single-property changes
- Snapshots are safer for complex multi-node AI edits
- Named transactions show "AI: Generate Dashboard" in the undo history

# ADR-004: AI Model Gateway

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** The AI engine must be provider-independent and clearly distinguish local vs. remote inference.

## Decision
Implement a **ModelGateway** interface with pluggable adapters. Current adapters: `GeminiAdapter`, `OpenAIAdapter`. Future: local Ollama adapter.

## API
```typescript
interface ModelGateway {
  complete(request: ModelRequest): Promise<ModelResponse>;
  readonly inferenceMode: 'local' | 'remote';
  readonly providerName: string;
}
```

## Consequences
- Positive: Swap providers without changing AI engine logic
- Negative: Adapter overhead; must validate output from all providers

# ADR-005: React Compiler Strategy

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** The React compiler must produce maintainable, human-readable JSX without depending on AI for correctness.

## Decision
Build a **deterministic compiler pipeline** with a typed Intermediate Representation (IR). AI may suggest component names and semantic tags, but JSX, CSS, and layout generation are rule-based.

## IR Structure
```
DesignSnapshot → CompilerIR (component boundaries, layout primitives, token refs)
→ JSXEmitter → CSSEmitter → TokenEmitter → AssetCopier → ManifestEmitter
```

## Consequences
- Positive: Repeatable, testable, auditable output
- Negative: Does not handle highly custom effects automatically

# ADR-006: Project Persistence (POC)

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** POC runs in the browser; production will use Tauri native file system.

## Decision
Use **IndexedDB** for the POC phase to store versioned project snapshots. Expose a `ProjectStore` interface that can be backed by IndexedDB or native FS.

## Interface
```typescript
interface ProjectStore {
  save(project: Project): Promise<void>;
  load(id: string): Promise<Project>;
  list(): Promise<ProjectMeta[]>;
  export(id: string): Promise<Blob>; // .dforge package
}
```

# ADR-007: AI Action Safety

**Status:** Accepted  
**Date:** 2026-10-22  
**Context:** AI-generated design actions must not execute arbitrary code, access the file system, or modify unselected nodes without user awareness.

## Decision
Define an **allowlisted DesignAction schema**. The AI executor only processes actions matching this schema. All actions pass through the same command validator as manual edits.

## Prohibited AI actions
- Arbitrary JavaScript execution
- File system writes outside the project store
- Network requests to external services
- Modification of nodes outside the declared scope

## Consequences
- Positive: Safety, auditability, undo support
- Negative: Limits AI creativity; complex operations need multiple action steps
